Git, for someone who's never touched a terminal

Git tutorials love to start with branching diagrams and merge conflicts before you've even saved a single file. That's backwards. Here are the four commands that cover almost everything you need for your first few months, explained as what they actually do, not what they're called.

Think of it as a save-point system

A normal "save" overwrites your last save. Git instead keeps a full history of save points, called commits, that you can look back through or return to. You choose exactly when a save point gets created, and you write a short note describing what changed in it.

1. git status — what's different right now

Run this any time you're unsure what state your project is in. It lists every file you've changed, added, or deleted since your last save point. Get in the habit of running it before doing anything else — it costs nothing and tells you exactly where you stand.

git status

2. git add — choose what goes into the next save point

Changing five files doesn't mean all five need to be saved together. git add stages the specific files you want included in the next commit — think of it as putting items in a basket before checking out.

git add index.html
git add .   # or: stage everything that changed

3. git commit — actually create the save point

This takes whatever you staged with git add and locks it in as a permanent point in history, along with a message describing what changed.

git commit -m "Fix broken login button on mobile"
Write commit messages for the person who reads them six months from now — probably you. "Fix bug" tells future-you nothing. "Fix broken login button on mobile" tells you exactly what to expect if you ever need to look back.

4. git push — send your save points somewhere else

Everything so far happens only on your own machine. git push uploads your commits to a remote copy of the project — usually on GitHub — so they're backed up and visible to anyone else working on it.

git push

The loop, in order

In practice, those four commands run in the same order almost every time:

git status          # see what changed
git add .           # choose what to save
git commit -m "…"   # save it with a message
git push            # send it upstream

Why this is enough for a long time

Branches, merges, and rebasing are real skills you'll eventually want — but they're solving problems you won't run into on day one. Save-check-commit-push covers the vast majority of what a beginner actually does with Git, and it's a much smaller thing to hold in your head than the full manual makes it look.
