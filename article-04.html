Prompting an AI coding agent well

I build things with an AI coding agent every single day, and the single biggest skill I've had to learn has nothing to do with programming languages — it's learning how to ask for what I want. A vague prompt gets a vague result. A specific one gets something close to done on the first try.

The prompt that stalls

Here's a prompt I actually used to write, back when I didn't know better:

"Make a login page."

Technically answerable, practically useless. The agent has no idea what framework you're using, what your existing files look like, whether you want email/password or social login, or what "done" even means here. It'll guess — and every wrong guess costs you a round trip of reading code, realizing it's not what you meant, and re-explaining.

The prompt that ships

Compare that to this:

"Add a login form to src/pages/Login.jsx. It should match the existing style in src/pages/Signup.jsx — same layout, same Tailwind classes. Fields: email and password, both required. On submit, call the existing loginUser() function from src/api/auth.js and show its error message under the form if it rejects. Don't add a 'remember me' checkbox or social login — just the two fields."

Same task, dramatically different outcome. This version gives the agent four things a vague prompt never does:

  • Location — exactly which file to touch.
  • A reference point — an existing file to match style and structure against, instead of inventing a new pattern.
  • Constraints — what to build, and just as importantly, what not to build.
  • The existing pieces to reuse — so it doesn't reinvent a login function that already exists somewhere else in the project.

Treat it like a loop, not a vending machine

The biggest mindset shift: don't expect one perfect prompt to produce one perfect result. Expect a short loop — ask, read the actual diff it produced, correct one specific thing, ask again. Two or three tight iterations with real feedback beat one giant paragraph trying to anticipate everything up front.

Give it the error, not your interpretation of the error

When something breaks, paste the actual error message and the relevant code, not your summary of what you think went wrong. "It's not working" forces the agent to guess at the same problem you're stuck on. The raw traceback (see reading an error message without panicking) usually gets fixed in one pass.

Vague in, vague out. The agent isn't reading your mind — it's reading your prompt, plus whatever files you point it at. Specificity is the whole skill.

Why this matters more than knowing syntax

You don't need to memorize a language's full syntax to build real things anymore — but you do need to describe what you want with enough precision that "what you want" and "what got built" are the same thing. That's the actual skill underneath "prompting well," and it transfers to every project, every framework, and every future tool that works the same way.
